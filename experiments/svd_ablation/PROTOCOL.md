# SVD feature ablation

Fixed before inspecting ablation results. Base: main at 50a64e4.

Question: does adding historical SVD features to item means, online ridge and
trust improve prequential predictions and reduce target label cost?

Use the Stage 9 `budget_prediction95` pipeline reused in Stages 10–12, with
its original statistical rules, certified error allocation, raw95 intersection, repairs,
ridge priors, clipping, trust update, stakes, precision .05 and stopping rules.
The original arm uses default rank 3. The ablation calls the same historical
feature function with rank 0: item means and the intercept remain, and only
SVD feature columns disappear. Intercept ridge penalty remains .25. Trust and
variance-dependent stakes follow identical rules but may realize different
values as predictions change. No tuning or feature replacement is allowed.

Use all original WMT23 leave-one-system-out pools, all 39 targets, three
historical conditions (aligned, permuted, reversed), 100 repeats per arm and
the original case seeds. Both arms independently generate uniform queries
without replacement. Require identical ledgers across arms and with saved
Stage 9 ledger hashes. Historical fits exclude the target system. Verify the
unchanged arm's average label costs against all 117 Stage 9 reference rows.

Prediction metrics use the effective trusted probability committed before
each label is revealed: MSE (Brier score for binary outcomes), MAE, residual
mean and population residual variance (ddof=0) within each repeat's full path.
The full common horizon, including diagnostic queries after stopping, avoids
comparing predictions over different selected stopping horizons. These extra
diagnostic queries do not count toward reported label cost. Residual variance
means variance of Y minus prediction, not variance of the inference-corrected
draw. Calibration error is not separately assessed.

Label cost is the first nonempty interval of width at most .10; preserve full
path coverage and stopped absolute estimation error as validity diagnostics.
Average repeats within target, systems within language, then languages equally.
Report every historical condition, including unfavorable results. Paired mean
cost differences are SVD minus no-SVD. MCSE uses 100 repeat blocks, preserving
cross-target dependence; it measures query-randomization error on these fixed
development pools and is not a new-data confidence interval.

Save per-repeat metrics, target/language/overall summaries, paired comparisons,
input case metadata, source hashes, ledger hashes and artifact hashes. Full
curves are checked in memory and regenerated by the runner rather than saved.
Run tests for feature removal, isolation, canonical engine equivalence,
prediction timing, paired ledgers and independent metric reconstruction.
Run all existing stage tests separately and check release manifests.

Execution amendment before reading any ablation results: the original engine
was too slow on this runtime. The comparison uses an exact candidate-pruning
implementation in this directory for both arms. It omits unused model-free
betting branches and skips capital calculations for candidates permanently
excluded by raw95 or prediction capital. This changes no retained candidate's
rounded arithmetic, ridge/trust update, ledger, confidence endpoint or stopping
rule. Validate exact full curves, repair flags, ledgers and prediction metrics
against the unmodified engine in both arms, on synthetic paths and two repeats
from each real language pool. Also require all 117 original-arm average label
costs to equal the published reference. Retain the failed sandbox attempt and
the interrupted slow attempt metadata; neither contributes reported results.

No existing experiment source or result file may change. All additions belong
under experiments/svd_ablation on experiment/svd-ablation. Historical label
cost and future-release generalization are outside this experiment's scope.
